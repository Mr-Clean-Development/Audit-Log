## Summary

This PR migrates all phone-based applications from the legacy oph3z-phone system to the new sd-phone framework. The changes modernize the phone integration across multiple apps while maintaining their core functionality.

## Summary
All phone apps (CleanEats, CleanRide, Garage, Gun Tracker) have been updated to use sd-phone's native message passing API instead of the legacy oph3z-phone iframe-based system. This includes updated client-side registration, UI initialization, and message handling.

## Key Changes

**UI Layer Updates:**
- Replaced oph3z-phone iframe polling with sd-phone's native `window.addEventListener('message')` for receiving updates from Lua
- Updated NUI fetch endpoints from resource-based URLs to `https://cleaneatsr/` format
- Added explicit body visibility handling in HTML files to prevent flash of unstyled content
- Removed dependency on parent window postMessage for toast notifications in CleanEats

**Client-Side Registration:**
- Replaced old phone registration system with new `sd-phone:addCustomApp()` export
- Updated app configuration structure: `id` → `identifier`, `label` → `name`, removed `place`/`share`/`headerImage` fields
- Added `defaultApp` flag to app configs
- Implemented proper sd-phone startup detection with retry logic
- Added resource restart handlers for sd-phone

**Message Passing:**
- Implemented `sendCustomAppMessage()` for server-to-client app updates (tracking, driver status, notifications)
- Replaced polling-based state sync with event-driven message handling
- Updated NUI callbacks to use standard `RegisterNUICallback` pattern

**File Organization:**
- Consolidated client entry points: `client/main.lua` → `client.lua`
- Added `ui_page` manifest declarations for apps with UI
- Removed dependency on `nbla-phonekit` theme synchronization

**Configuration Updates:**
- Updated all app configs to use sd-phone compatible structure
- Removed phone resource references from dependencies (replaced with `sd-phone`)
- Cleaned up manifest files to remove obsolete phone-related declarations

## Implementation Details
- Apps now register with sd-phone on startup and re-register if sd-phone restarts
- Message passing uses postMessage API with action/data structure for bidirectional communication
- UI pages are now served directly via `ui_page` manifest instead of iframe injection
- All apps maintain backward compatibility with their existing server-side logic
